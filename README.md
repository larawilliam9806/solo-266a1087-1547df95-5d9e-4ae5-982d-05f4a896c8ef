# 环卫入仓台账

面向环卫月报的地磅单入仓网页。数据员选定首个待封月后，逐批上传待封月或已封月的
CSV；系统按街道汇总出当月净重与旧月调整，封存后自动进入下一个月。迟到补单与旧单
更正一律计入**当前待封月**，已封月的原表永不改动。

分拣称重单往往晚于地磅单到仓：数据员可另行上传**分拣 CSV**，按单号与入账修订号把
每笔净重拆到各垃圾类别。系统据此生成**分类月表**，缺分拣资料的重量计入「未分类」，
每月两列的分类合计始终与街道底表相符。

Flask + SQLite，单容器，附 Docker Compose 启动。

## 启动

```bash
# 生产（Docker Compose，数据落在命名卷 ledger-data）
SECRET_KEY="$(python3 -c 'import secrets;print(secrets.token_hex(32))')" \
  docker compose up --build -d
# 打开 http://localhost:8000
```

```bash
# 本地开发
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
DATA_DIR=./data SECRET_KEY=dev flask --app wsgi run --debug
```

数据文件默认为 `$DATA_DIR/ledger.db`（容器内 `/data/ledger.db`）；也可用
`LEDGER_DB` 直接指定完整路径。首次启动会自动建表。

`SECRET_KEY` 请在生产环境固定下来：它用于会话与 CSRF 令牌，随机生成会导致重启后
所有页面令牌失效。

### 容器说明

命名卷首次挂载时归 root 所有。`entrypoint.py` 仅在以 root 启动时把 `/data` 的属主
改成 `appuser`，随后降权运行 gunicorn；`/healthz` 供 Docker healthcheck 探活。
若要跳过降权（例如 Podman 无根模式），设置 `DROP_PRIVILEGES=0` 并以非 root 用户运行。

## 使用流程

1. **选定首个待封月**（如 `2026-10`），成为第一份待封底表。
2. **逐批上传 CSV**。每行五列：

   | 列 | 说明 |
   | --- | --- |
   | 单号 | 地磅单号，全局唯一 |
   | 清运月 | `YYYY-MM`；同一单号一经入账即固定 |
   | 街道 | 汇总维度 |
   | 净重（千克） | 最多三位小数；负数拒绝 |
   | 修订号 | 正整数，只能递增 |

   表头可用常见别名（`净重(kg)`、`重量`、`版本号` 等）；编码支持 UTF-8/BOM、
   UTF-16、GB18030；分隔符支持逗号、制表符、分号。
3. **查看底表**：每个街道两列——`当月净重`（清运月等于该月）与`旧月调整`
   （清运月早于该月），合计为两者之和。
4. **封存**该月，进入下一个月。封存后底表冻结。
5. **换交分拣资料**：在「分类月表」页上传分拣 CSV，按垃圾类别核算月报（见下）。

## 分拣资料与分类月表

分拣称重单可晚于地磅单到仓，两份资料分别上传、互不阻塞。

### 分拣 CSV

每行四列：

| 列 | 说明 |
| --- | --- |
| 单号 | 已入账的地磅单号 |
| 修订号 | 该笔**实际入账**的修订号；只推进修订号、内容未变的版本不记账，不能填写 |
| 类别 | 垃圾类别；`未分类` 是系统保留名，禁止使用 |
| 克重 | 非负整数克，不接受小数或单位后缀 |

表头同样支持常见别名（`版本号`、`垃圾类别`、`重量克` 等）与 UTF-8/BOM、UTF-16、
GB18030 编码。规则：

- **每笔每类只填一行**；同一笔同一类别在文件内重复，整批退回。
- 同一笔（单号 + 修订号）各类克重之和**必须等于该笔入账净重**，否则整批退回。
- 单号必须已入账，修订号必须是该单号实际入账过的修订号，不能超过当前修订号。
- **换交即整份替换**：本次列出的每一笔，其旧分类先整体删除再写入新分类；未列出的
  其他笔次不受影响。任何校验或保存失败都回滚整笔事务，**原分类保持不变**。

### 分类月表

在 `/classify` 按入账月份范围查询（逐月列出，含区间内无数据的月份）。每月对每个
垃圾类别给出 `当月净重` 与 `旧月调整` 两列，并在表尾同时给出分类合计与**原底表
合计核对**两行：两列各自相等，缺分拣资料的重量计入保留类别`未分类`。

- **冲回按被冲回那笔入账的分类扣减**。原入账即使早于查询范围，或期间只改过修订号
  （no-op 推进），也按最近一次实际入账版本的分类处理。
- **补交或更正分类后**，原入账与对应冲回在分类月表里同时改归；已封存的街道底表
  快照不受影响，照常下载。
- 页面另列**待补分拣资料**：查询区间内缺分类的入账单号与有效入账修订号（零重量
  入账除外）。
- 整次查询在一个只读事务内完成，使用同一份账目与分拣资料快照；查询期间可继续
  收单、封存和换交，已打开的报告不受新提交影响。

## 入账规则

**同单号、清运月固定。** 同一单号再次出现时清运月必须一致，否则整批退回。

**修订比较。** 以已入账的当前修订号为基准：

| 上传的修订号 | 内容 | 结果 |
| --- | --- | --- |
| 小于当前 | 任意 | 旧版，沿用当前值（no-op） |
| 等于当前 | 与已入账完全一致 | 原样重传，沿用当前值（no-op） |
| 等于当前 | 街道或净重不同 | **整批退回** |
| 大于当前 | 与已入账完全一致 | 仅推进修订号（no-op） |
| 大于当前 | 有变化 | 更正：先冲回旧街道，再补记新街道 |

**整批原子。** 任一行校验失败（含表内单号重复、清运月晚于待封月、清运月冲突、
当前版本被改），整批一行都不写：单据、入账记录与底表保持原样，接口返回逐行原因。

**迟到与更正归入当前待封月。** 补单直接按净重记入；更正先按上次入账版本冲回
**原街道**的净重，再向**订正后的街道**补记新净重。两步在同一事务内，要么都入账，
要么都不入账。因此已封月的底表不变，差额体现为当前待封月的「旧月调整」。

**封存不可变。** 封存时把整张底表写入快照。下载、再次封存同一月份，都返回该快照
原表；补单与更正不会触碰它。封存只能封当前待封月，且封存后日历前进一个月。

**并发。** 每次上传、封存都在 `BEGIN IMMEDIATE` 事务中执行，SQLite 写锁把它们排成
一个序列，按**提交生效的先后**决定批次归入哪个月。若上传先提交则该批计入封存前的
月份；若封存先提交则该批计入新开的月份。两半更正与批次记录同事务提交，进程中断或
校验失败时全部回滚。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 总览与上传 |
| POST | `/initialize` | 选定首个待封月（仅一次） |
| POST | `/api/upload` | 上传地磅 CSV，返回 JSON |
| POST | `/api/sorting` | 上传分拣 CSV（换交分类），返回 JSON |
| GET | `/classify` | 分类月表页面（参数 `start`、`end`） |
| GET | `/api/classification` | 分类月表 JSON（参数 `start`、`end`） |
| POST | `/seal` | 封存月份 |
| GET | `/month/<YYYY-MM>` | 某月底表 |
| GET | `/month/<YYYY-MM>/download` | 下载已封月原表 CSV |
| GET | `/api/state` | 状态 JSON（含最近分拣批次） |
| GET | `/template.csv` | 地磅 CSV 模板 |
| GET | `/sorting-template.csv` | 分拣 CSV 模板 |
| GET | `/healthz` | 探活 |

写操作需要 CSRF 令牌（表单字段 `csrf` 或请求头 `X-CSRF-Token`）。上传可带
`target_month` 声明单据所属月份；它必须是当前待封月或某个已封月，实际入账月份
始终是当前待封月。

错误 JSON 形如：

```json
{"ok": false, "code": "batch_rejected", "error": "批次校验未通过，整批退回，未写入任何数据",
 "details": [{"line": 3, "ticket_no": "WB-1", "message": "……"}],
 "detail_count": 1, "details_truncated": false}
```

## 金额精度

净重以**克**为整数存入 SQLite，避免浮点累加误差。录入最多三位小数（即 1 克），
超出精度的值直接拒绝而不是静默四舍五入。下载与页面展示时再格式化为千克。
